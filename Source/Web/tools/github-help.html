GitHub ve Zpěvníku 3.1.9 – nastavení pracovního NTB a domácího PC

Co tím získáš

Oba počítače používají stejný repozitář, větev a podsložku. GitHub je společné místo pro data, každý počítač má vlastní místní kopii a funguje i bez internetu. Žádný počítač repozitář nezamyká. Otevřený zpěvník v práci nebrání práci doma.

Synchronizují se uložené písně, databáze akordů, fotografie interpretů, obaly, seznamy, sdílené nastavení a manifest. Výběr Databáze – Data pracuje s daty. Výběr Aplikace – Source a Licenses samostatně porovnává zdroje a licence v kořeni repozitáře. EXE se neposílá.

1. Vytvoř repozitář

Na GitHubu se přihlas pod svým účtem. Tlačítkem + otevři New repository. Jako název můžeš použít zpevnik. Pro současné používání pouze tebou zvol Private; přístup na obou počítačích bude přes tvůj token. Zapni vytvoření README a klikni Create repository. README zajistí, že existuje první verze a větev. Poznamenej si název větve z nabídky nad soubory; obvykle je main.

Existující repozitář nemusíš zakládat znovu. Jestli už jsi do něj publikoval z verze 3.1.7, ponech stejnou větev i podsložku. Změnou podsložky by vzniklo jiné umístění dat.

Oficiální postup: https://docs.github.com/en/repositories/creating-and-managing-repositories/creating-a-new-repository

2. Vytvoř token

Token je klíč, kterým se aplikace připojuje k tvému repozitáři. Neposílej ho do chatu ani nevkládej do projektových souborů.

Na GitHubu otevři profilový obrázek → Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token.

• Token name: například Zpevnik pracovni NTB.

• Expiration: zvol dobu platnosti, například 90 dní.

• Resource owner: tvůj účet.

• Repository access: Only select repositories, vyber zpevnik.

• Repository permissions: Contents nastav na Read and write. Ostatní oprávnění nepřidávej; Metadata může být přidané automaticky.

• Generate token: zkopíruj zobrazený klíč a ulož si ho do správce hesel.

Pro domácí PC vytvoř druhý token, například Zpevnik domaci PC, se stejným přístupem. Každý počítač pak můžeš spravovat samostatně.

Oficiální postup: https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens

3. Vyplň Zpěvník na prvním počítači

Nainstaluj aktualizaci 3.1.9: zavři zpěvník, nahraď EXE a Source. Zachovej dosavadní Data a settings.json. Spusť Zpevnik.exe a otevři Nástroje → GitHub.

Příklad: adresa repozitáře je https://github.com/TVUJ_UCET/zpevnik.

Pole v aplikaciCo zadat
Vlastník GitHub účtuTVUJ_UCET – skutečné uživatelské jméno z adresy
Repozitářzpevnik – pouze název, bez celé adresy a bez .git
Větevmain, případně přesný jiný název větve
Podsložka databázeData pro nový projekt s daty oddělenými od zdrojů
Přístupový tokenKlíč vytvořený pro tento počítač

Velikost písmen ve větvi a podsložce zachovej přesně. Pokud už máš data v kořeni repozitáře, pole podsložky nech prázdné. V obou počítačích musí být toto nastavení shodné.

Klikni Uložit nastavení. Údaje o repozitáři si aplikace pamatuje. Token se ukládá šifrovaně pro účet Windows i pro další spuštění. Tlačítkem Zapomenout token ho odstraníš. Pro soukromý repozitář je nutný i ke čtení. Veřejnou databázi lze číst bez tokenu, zápis vždy potřebuje oprávnění.

4. První naplnění GitHubu

Nejprve ulož rozpracované písně v editoru. Klikni Porovnat změny. V novém repozitáři budou soubory označené šipkou nahoru. Klikni Synchronizovat obě strany. Po dokončení budou na GitHubu v Data písně, obrázky, akordy, database.json, artists.json, config.json a manifest.json. Indexy a manifest sestavuje aplikace.

První přenos může trvat několik minut. Počkej na zprávu o dokončení. Tlačítkem Verze na GitHubu můžeš otevřít výsledek. Další synchronizace přenáší pouze rozdíly.

5. Nastav druhý počítač

Na druhém počítači potřebuješ funkční instalaci zpěvníku se složkou Data. Pokud ji ještě nemáš, jednorázově přenes celou stávající složku aplikace. Samotný aktualizační ZIP data neobsahuje. Pokud tam už zpěvník používáš, jeho Data ničím nepřepisuj; pouze aktualizuj EXE a Source.

Vyplň stejného vlastníka, repozitář, větev a podsložku. Použij token pro druhý počítač. Potom Porovnat změny → Načíst z GitHubu.

Při úplně prvním propojení aplikace nemusí znát společný stav obou kopií. U rozdílných souborů proto požádá o volbu. Pokud je aktuální verze z prvního počítače už na GitHubu a zde nemáš vlastní nové úpravy, zvol Použít GitHub. Pokud máš na druhém počítači novější vlastní práci, prohlédni obě verze před rozhodnutím. Neporovnáváme stáří podle hodin Windows.

6. Běžný den

Po příchodu k počítači: otevři GitHub ve zpěvníku, vlož token, Porovnat změny a Načíst z GitHubu. Po dokončení klikni Obnovit zpěvník po načtení. Pak upravuj písně.

Před odchodem: ulož všechny rozpracované změny v editorech, Porovnat změny a Synchronizovat obě strany. Počkej na dokončení. Potom můžeš aplikaci zavřít nebo ji nechat otevřenou – druhý počítač nic neblokuje.

Volba Při otevření zpěvníku zkontrolovat změny pouze upozorní na rozdíly. Sama nic nepřepisuje ani neodesílá. U soukromého repozitáře po novém spuštění nejprve potřebuje token; případné upozornění na nedostupnost nebrání práci s místními daty.

Jak číst porovnání

• ↑ Z tohoto počítače na GitHub: místní novinka nebo úprava. Samotné Načíst z GitHubu ji zachová, ale neodešle.

• ↓ Z GitHubu do počítače: novinka či úprava z druhého počítače.

• ↔ Sloučit nezávislé změny seznamu: doplňující se metadata seznamů se spojí. Seznam písní a počty se znovu sestaví z písní.

• ⚠ Změněno na obou stranách: konflikt; oba akční knoflíky počkají, dokud nevybereš verzi u každého konfliktu.

Porovnat obsah zobrazí místní a vzdálený JSON nebo obrázky vedle sebe. Ponechat místní zachová celý místní soubor; Použít GitHub zvolí celý vzdálený soubor. Text písně se automaticky neslepuje, aby se nepromíchaly akordy a sloky. Při potřebě obou úprav si obsah nejprve spoj v editoru a pak zopakuj porovnání.

Načíst z GitHubu nikdy nezapisuje do repozitáře. Zachovává tvé nepublikované změny a provede vybrané řešení konfliktů. Synchronizovat obě strany navíc odešle výslednou společnou verzi a sjednotí místní data.

Zálohy a důležité chování

Přepsané místní soubory jsou zálohované v Data/.backups. Poslední známý společný stav je v Data/.sync, odděleně pro každý repozitář, větev a podsložku. Tyto složky se na GitHub neposílají; .sync ručně nekopíruj mezi různými rozpracovanými knihovnami ani nemaž. Chybějící stav způsobí nové první porovnání s opatrnou volbou konfliktů.

Mazání souborů se zatím nesynchronizuje: existující kopie na druhé straně se zachová či obnoví. Změny ve zdrojích aplikace jsou v samostatném výběru Aplikace – Source a Licenses. Soukromé přihlašovací údaje z místního configu se neodesílají.

Rozpracovaný text, který ještě nebyl uložený v editoru, není součástí synchronizace. Po načtení dat obnov zpěvník. Pokud máš otevřený starší koncept písně, editor může správně odmítnout jeho uložení přes novější soubor; znovu načti píseň a přenes požadované úpravy.

Když něco nejde

• 401: token je neplatný nebo vypršel. Vytvoř nový a vlož ho do aplikace.

• 403: zkontroluj Contents: Read and write, pravidla větve nebo omezení požadavků GitHubu.

• 404: zkontroluj vlastníka, název a větev; u Private repozitáře také token a jeho přístup.

• GitHub se od porovnání změnil: druhý počítač mezitím publikoval. Znovu Porovnat změny.

• Místní data se změnila: mezitím se něco uložilo. Znovu Porovnat změny.

• Výpadek připojení: soubory zůstávají místně. Po obnovení připojení proveď nové porovnání skutečného stavu.

• GitHub byl aktualizován, ale místní data nebyla synchronizována: vzdálený zápis proběhl, během něj se ale změnila místní data nebo selhalo ukládání. Nepřepisují se. Proveď nové porovnání.

Až budeš připravovat běžnou aplikaci pro další lidi nebo TV, nedávej do ní svůj zapisovací token. Způsob čtení společné databáze a případné veřejné zpřístupnění zvolíme pro tuto distribuci zvlášť.

Source a Licenses v GitHub manageru

V části Obousměrná synchronizace přepni Co synchronizovat na Aplikace – Source a Licenses. Pak Porovnat změny. Připojení a token zůstávají stejné jako pro Data.

Pro repozitář angelexit/zpevnik je datová podsložka Data. V režimu aplikace se ale vždy porovnává /Source a /Licenses v kořeni repozitáře; nevytváří se Data/Source. Místní zdroje a licence se čtou vedle spuštěného Zpevnik.exe. Názvy Source a Licenses rozlišují velikost písmen na GitHubu.

Pokud jsou na GitHubu starší zdroje 3.1.5 a právě jsi nainstaloval tuto aktualizaci včetně složky Source, použij pro soubory, které chceš aktualizovat, Ponechat místní. Po kontrole můžeš použít i U všech konfliktů ponechat místní a následně upravit jednotlivé výjimky. Synchronizovat obě strany je odešle; Načíst z GitHubu nic neodesílá.

Stejně jako u dat se před přepsáním zálohuje a nepřenáší se mazání. Zdrojové zálohy a společný stav jsou ve složkách .backups a .sync vedle EXE. Datové zálohy zůstávají v Data/.backups.

Přenášejí se zdrojové soubory (C#, JavaScript, HTML, CSS, JSON, skripty sestavení), fonty, obrázky a licence. Vynechávají se EXE/DLL, bin, obj, node_modules, .git, dočasné soubory, web.zip, settings.json, .env a soubory secrets/credentials. Soubory, které už na GitHubu existují mimo tento rozsah, se nemažou.

Stažením Source se spuštěná EXE nezmění. Manager zdroje automaticky nesestavuje ani nespouští. Pro novou funkční verzi EXE používej dodanou aktualizaci, nebo ji sestav ze zdrojů podle vývojového návodu. Pokud pracuješ ve vývojovém režimu Spustit-vyvoj.cmd, načítají se webové zdroje přímo ze Source; po jejich synchronizaci aplikaci restartuj.
